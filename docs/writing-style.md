# Writing style

The authoritative writing rules for this repository. They govern anything produced here: chat
prose, code comments, ADRs, commit messages, and every governing document.

These rules are the author's, applied to this repository's own prose. They are not a general
style guide and they are not up for debate inside a contribution; they exist so that everything
written here reads as one voice.

## Cuts, never use in prose

- **Em-dashes** in any prose context. Use periods, colons, parentheses, or sentence breaks.
  The carveout is exactly this list and nothing else:
  - Code comments inside backtick blocks
  - File header comments
  - Running headers
- **"Not X, it's Y"** parallel constructions.
- **Manufactured triplets** that do not earn their parallelism.
- **Filler intensifiers**: specifically, essentially, particularly, actually, honestly, genuinely,
  basically. Drop them even when grammatically defensible.
- **Hedge phrases**: "I would argue", "it seems", "perhaps", "arguably". Take a position.
- **Corporate verbs**: leverage, enable, facilitate as fluff, reframe, elevate, delve, unpack,
  dive into. "Facilitate workshops" is fine; facilitating an outcome is not.
- **Empty corporate-polite framing.**
- **Strained analogies** reaching for meaning.

## Adds, use these

- First-person opinions: "I have seen", "in my experience", "I would not".
- Short and long sentences mixed.
- Direct opinions stated plainly: "This is wrong." "Avoid that." "Get this right."
- Questions occasionally.
- Bold lead-ins for parallel subsections: `**Name of point.**` followed by elaboration.
- Sentence fragments for emphasis: "Latency drops to milliseconds."
- Specifics over generic claims.

## Preserve, never modify

- Technical content and specific facts.
- Code samples. Do not reformat them.
- Structure. Do not rearrange sections to suit a sentence.

## How to apply it to a pass

1. Read the whole section for tone first.
2. Identify the intended punch line of each paragraph.
3. Look for em-dashes. Mechanical.
4. Look for filler intensifiers. Mechanical.
5. Look for manufactured triplets and hedge phrases. Judgment.
6. Read it aloud, mentally, for rhythm.

## What this file is not

It is not a source of prose to imitate. It is a list of rules to apply.
